# Implementation coverage matrix

Maps every section of the master architecture (`docs/architecture/DLY_AEOS_Master_Architecture_Final.md`)
to the owning control-plane modules, representative tests, the dominant evidence level of the
tested requirements, and what is still NOT-PROVEN or needs an owner action. Referenced by the
README milestone table, ADR-0001 and AGENTS.md.

**Snapshot, not a live status.** The requirement counts come from the exhaustive audit of
2026-10-19 (1,656 requirements, each classified IMPLEMENTED_TESTED / IMPLEMENTED_UNTESTED / PARTIAL /
MISSING / DESIGN_ONLY_OK / NOT_APPLICABLE / BLOCKED_EXTERNAL / OWNER_DECISION) and were taken
**before** the wave-3 fixes; the fixes are tracked in their pull requests. Live readiness is the
Readiness Doctor (`aeos doctor`, `/readiness`); acceptance rows are in
[tests/acceptance/MATRIX.md](../tests/acceptance/MATRIX.md). Evidence levels E0-E4 follow ADR-0061.
Nothing here claims a capability works unless a listed test or the Doctor proves it (§48).
