### Security

- **The broker publishes a worker run only after a Claude review PASS of its exact head.** Owner rule R44 (2026-10-28): everything OpenCode and OpenRouter produce goes through a Claude review, and a worker may not commit, push or merge. The broker accepted any run in REVIEW or DONE with a runtime head, so a candidate could reach an `aeos/*` branch and a pull request before any review verdict existed. Every remote write of a worker run - the branch push and pull-request creation, on GitHub and on Bitbucket - now needs the run's latest Claude checkpoint review to be COMPLETED, not MOCK, a PASS that its own HIGH/CRITICAL findings do not contradict, answered by an Opus model (owner rule 2026-10-28: the checkpoint review is Opus, never Fable; a Fable review is recorded but never publishes) that also satisfies the review policy, of a package that showed the reviewer the whole diff (not truncated at 60,000 characters: split the task), and bound to exactly the head being published through its checkpoint package evidence; the push also publishes only the runtime's single candidate commit on the run's base, so worker-made commits (a file added and deleted again, invisible in the reviewed diff) never leave the machine. Otherwise `REVIEW_REQUIRED` ("no Claude review PASS for head <sha12>: ..."), audited with a reason (`NO_REVIEW`, `OTHER_HEAD`, `TRUNCATED`, `HISTORY`, `NOT_PASS`, `FINDINGS`, `MODEL`, ...), before any grant, credential or request (`HISTORY` in the broker's mirror, before the push); `prepare-pr` keeps the code. Git in a worker's environment now refuses every remote transport (only `file`; ssh and askpass are a failing command; no credential helper), also for a `worktree` candidate that shares the owner's repository config. The quarantine release rule and every other broker check are unchanged, and the broker still has no merge operation. New tests also prove at the seams that a worker cannot publish by itself: git in the worker's sandbox finds no code-host credential even when the owner's home holds one and refuses an ssh remote served by a fake ssh (the owner's own push over it works), the isolated candidate has no remote, and a push or PR capability token reaches no publication route. ADR-0132. Evidence: E2 unit runs on macOS arm64, each refusal red on the previous code with its own message and a near miss green; NOT-PROVEN on Windows and macOS Intel until CI runs, and against live GitHub and Bitbucket (local bare remotes, mocked HTTP).
