### Security

- **The broker publishes a worker run only after a Claude review PASS of its exact head.** Owner rule R44 (2026-10-28): everything OpenCode and OpenRouter produce goes through a Claude review, and a worker may not commit, push or merge. The broker accepted any run in REVIEW or DONE with a runtime head, so a candidate could reach an `aeos/*` branch and a pull request before any review verdict existed. Every remote write of a worker run - the branch push and pull-request creation, on GitHub and on Bitbucket - now needs the run's latest Claude checkpoint review to be COMPLETED, not MOCK, a PASS that its own HIGH/CRITICAL findings do not contradict, answered by an Opus model (owner rule 2026-10-28: the checkpoint review is Opus, never Fable; a Fable review is recorded but never publishes) that also satisfies the review policy, of a package that showed the reviewer the whole diff (the diff evidence was readable, not truncated at 60,000 characters - split the task - and with no binary file, refused rather than shown as bytes; the verifier now reads the candidate only through the git dir the runtime recorded - never the worker-editable `.git` pointer - with no replace refs, in-tree attributes from the empty tree (git 2.41 or newer) and no global, XDG or system attributes file, and blocks a git dir with replace refs, grafts, `info/attributes` or a `commondir`/`gitdir` redirect, reads no global or system git config, shows submodule entries whatever their ignore settings and blocks a head with a submodule (unsupported for worker candidates), so a worker's `* -diff`, a planted git dir or a hidden submodule can no longer hide a change; numstat keeps paths with tabs, a changed path without a numstat entry counts as binary, a file name with a control character is refused, a missing scope evidence is refused like a missing diff, and a `.gitattributes` or `.gitmodules` change goes to special review), and bound to exactly the head being published through its checkpoint package evidence; the push also publishes only the runtime's single candidate commit on the run's base, so worker-made commits (a file added and deleted again, invisible in the reviewed diff) never leave the machine. A pull request is opened only after the broker's own push of exactly that head, and a PR whose reported head is another commit, too short a hash or missing is not counted. Otherwise `REVIEW_REQUIRED` ("no Claude review PASS for head <sha12>: ..."), audited with a reason (`NO_REVIEW`, `OTHER_HEAD`, `DIFF_UNAVAILABLE`, `TRUNCATED`, `BINARY`, `HISTORY`, `NOT_PUSHED`, `NOT_PASS`, `FINDINGS`, `MODEL`, ...), before any grant, credential or request (`HISTORY` in the broker's mirror, before the push); `prepare-pr` keeps the code. Git in a worker's environment now refuses every remote transport (only `file`, with git's `user` default; ssh and askpass are a failing command; no credential helper; ssh, https, http, git and ext each `never` so a repository config cannot re-enable one), also for a `worktree` candidate that shares the owner's repository config. The quarantine release rule and every other broker check are unchanged, and the broker still has no merge operation. New tests also prove at the seams that a worker cannot publish by itself: git in the worker's sandbox finds no code-host credential even when the owner's home holds one and refuses an ssh remote served by a fake ssh (the owner's own push over it works), the isolated candidate has no remote, and a push or PR capability token reaches no publication route. ADR-0132. Evidence: E2 unit runs on macOS arm64, each refusal red on the previous code with its own message and a near miss green; NOT-PROVEN on Windows and macOS Intel until CI runs, and against live GitHub and Bitbucket (local bare remotes, mocked HTTP).
