### Changed

- **One attribution implementation.** The repository hygiene test no longer keeps its own attribution regexes (co-author, bot, generated-with, vendor address); it reads every tracked file through `find_ai_attribution` / `ai_identity_problem` of `aeos.core.attribution` (AGENTS.md invariant 11, ADR-0121). This prevents the 2026-10-26 incident class in which a parallel regex set drifted from the guard and produced misses and false positives. Product prose the guard reads as a statement about who produced the text is accepted only through a short reviewed list (file, finding code, line fragment) whose stale entries fail the scan. Evidence: E2 (unit run on macOS arm64); NOT-PROVEN on Windows and macOS Intel until CI runs there.
- **Guard-sample exemption is decided on the syntax tree.** A test file may hold attribution samples only if it really imports `aeos.core.attribution` (import or from-import); a comment, docstring or string that merely names the module no longer exempts it. The five guard-consumer test files that relied on the old text marker now import the guard and assert that their samples are attribution for it. Evidence: E2 (bite tests: comment-only marker is red, real import is green); NOT-PROVEN on Windows.
- **Ratchet `test_single_attribution_implementation`.** An AST scan of `backend/`, `scripts/` and `tests/` fails when a `re.compile` / `re.search` / `re.sub` ... call (also via `from re import ...` or an alias) has a constant pattern, a concatenation of constants, an f-string or a module-level constant that matches an attribution marker (co-authored-by, generated with/by, a noreply address at an AI vendor) outside `backend/aeos/core/attribution.py`. Evidence: E1 static plus E2 bite tests (a split `co-` + `authored-by:` pattern is red, comments, strings, docstrings and unrelated patterns are green); the pre-refactor hygiene test is flagged by it; NOT-PROVEN on Windows.
- **Ratchet and reviewed-prose hardening (verifier findings).** The ratchet now also tests behaviour: a constant pattern that compiles and finds a probe attribution statement (co-authored-by, generated/created/written with/by/using, a noreply address at any AI vendor domain, including short labels such as groq or x.ai) but not its neutral decoy is flagged, so `[Cc]o-[Aa]uthored-[Bb]y:`, `(?:co-authored|signed-off)-by:` and a copy of the guard's verb alternation can no longer pass; generic validators (e-mail, host:path, name) stay green. Python files are parsed from bytes (a UTF-8 BOM no longer hides a pattern or a guard import) and a file that cannot be parsed is reported instead of skipped. A reviewed prose line is accepted only when it has no finding once all its reviewed fragments are removed, so a real attribution appended to a reviewed line is red; the stale-entry check is a helper (`scan_attribution`) with its own bite tests. Identity samples use a neutral placeholder name. Evidence: E2 (bite tests for each form, a near-miss for each); NOT-PROVEN on Windows and macOS Intel.
- **Known gaps of the canonical guard, reported not patched.** Forms the old hygiene regexes caught that `find_ai_attribution` does not: a trailer behind a comment prefix (`# `, `// `, `## `), `Co-Authored-By: Devin` (with or without an address) and `Generated with devin`, and `Generated by Cursor` (bare Cursor). They are recorded as strict-xfail tests in `tests/unit/test_core_attribution.py`; the fix belongs in `backend/aeos/core/attribution.py` (comment prefix in the trailer line prefix, devin and bare cursor with a component guard), after which the xfail turns red and the cases move to the caught list. Evidence: E2 (verified red on macOS arm64); NOT-PROVEN on Windows.
