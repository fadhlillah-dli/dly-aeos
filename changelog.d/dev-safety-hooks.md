### Added

- **Wrong-commit and identity guards in the pre-push hook.** Before any gate, `scripts/gates.py --hook` refuses a push when `HEAD` is detached and is not a pushed commit or an ancestor of one, or when a pushed `refs/heads/<current branch>` is not `HEAD`; it prints both shas and `git branch -f <branch> HEAD` after an ancestry check. It also refuses a push whose new commits are not authored and committed by the repository's `git config user.email`, or carry an AI identity or attribution (`aeos.core.commit_identity`, `aeos.core.attribution`), with the exact fix and no address printed; the printed `git rebase -r` fix re-authors only commits that `origin/main` does not already have. Prevents the incident class of 2026-10-26, where a worktree left on a detached `HEAD` sent a push and a pull request out on an old commit, and the class of commits pushed under the wrong identity. Evidence: E1 static review; E2 bite tests on macOS arm64 (real `git push` from a temporary clone to a temporary bare remote: detached `HEAD`, stale branch ref and wrong author refused, a normal push allowed). NOT-PROVEN on Windows and Intel macOS (the push tests skip on Windows).
- **Merge-conflict gate, NOT RUN lines and one verdict line in `scripts/gates.py`.** A `merge-conflict` gate fails when `git merge-tree --write-tree origin/main HEAD` reports conflicts (or any failure other than git's pre-2.38 usage error, for example unrelated histories) and lists the files (prevents pushing a branch that needs a conflict-resolution commit and a full CI re-run). Every job of `ci.yml` that the run does not execute is printed as `NOT RUN: <job> (<reason>)`, and the output ends with `GATES: PASS|FAIL (<n> run, <m> failed, <k> not run)` (also with `--json 2>&1`: stdout is flushed before the verdict); `--report <path.json>` writes the same result to a file that output filters cannot hide. A local PASS no longer reads as a CI PASS. Evidence: E1 static; E2 unit and bite tests on macOS arm64 (conflicting branch FAIL, clean branch PASS). NOT-PROVEN on Windows and Intel macOS.
- **`scripts/preflight.py --facts` and `scripts/run_tests.sh`.** ASCII environment facts (Python and venv, pytest and xdist, node, npm, git, `core.hooksPath`, shell, `gh auth status` exit status only) are printed at the start of a gate run, and never fail it. `run_tests.sh` (bash, `set -euo pipefail`, arguments in arrays) runs `pip check` and imports pytest and xdist before pytest, stops naming the missing package, supports a portable `--deadline` through `scripts/run_with_deadline.py`, and ends with `RUN_TESTS: PASS|FAIL rc=<n>`. Prevents background test runs that failed minutes in on a missing dependency or on an unsplit zsh variable. Evidence: E1 static (shellcheck clean); E2 bite tests on macOS arm64 (missing package stops before pytest, complete environment runs it, deadline kills a sleeping command). NOT-PROVEN on Windows and Intel macOS.
- **shellcheck in CI.** The `commit subjects [G1]` job (ubuntu-latest, pull requests) also runs `shellcheck scripts/*.sh scripts/git-hooks/pre-push`; no job or check name changed. A local `shellcheck` gate runs the same command (SKIPPED with a reason when shellcheck is missing), and the `commit-subjects` job counts as run locally only when it and the commit-subject gate both ran. `run_tests.sh` suppresses SC2317 as well as SC2329 for its trap handler and avoids `A && B || C`, so it is clean for the shellcheck 0.9 that ubuntu-latest ships as well as for newer ones. Prevents a quoting slip in a shell helper reaching the owner's machine, and a lint failure that differs by shellcheck version. Evidence: E1 static; E2 gate and accounting tests on macOS arm64 with a stand-in shellcheck. The scripts were NOT run through shellcheck 0.9 or 0.11 here (none could be executed), and the CI run itself is NOT-PROVEN until the pull request runs.
