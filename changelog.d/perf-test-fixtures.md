### Changed

- **Faster shared test fixtures.** The `settings` fixture now builds one migrated template database per test process (tables, append-only triggers, alembic head stamp) and gives each test its own copy through SQLite's online backup, so every test still starts from a fresh, identical database. The Argon2id hasher is wrapped once per session by a memo that still runs the real production-parameter hasher once per distinct password and (hash, password) pair (the identity tests still see the m=65536,t=3,p=4 profile). `tests/unit/test_doctor_seams.py` uses a cheap file-local hasher (its assertions never concern hash parameters) and runs the real in-process HTTP guard probe once per guard fingerprint instead of in every doctor run. Measured serially on Apple Silicon under a busy host (before -> after): test_doctor_seams 64.6 s -> 43.8 s (user CPU 74 s -> 28 s), test_identity 4.4 s -> 1.6 s, test_identity_hardening 2.3 s -> 1.8 s, acceptance/test_auth_boundary 2.6 s -> 2.1 s, test_doctor_api 8.4 s -> 5.2 s, test_operations_backup 11.0 s -> 3.9 s. No test, case or assertion was removed or weakened. The effect on Windows and macOS Intel runners is NOT-PROVEN until CI.
