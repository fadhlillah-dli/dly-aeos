### Fixed

- **Stale Control Center after git pull.** `git pull` updated the frontend source but `frontend/dist` (built 2026-10-26) was served for two days while five frontend commits were missing, and the Doctor only checked that `index.html` existed (LESSONS L23, owner request R28). New Doctor check `runtime.frontend_fresh` compares the Vite build record with `git rev-parse HEAD:frontend` through `release.ui_correspondence` (CONFIGURED `FRONTEND_STALE` on a mismatch, UNVERIFIED without a clean record; a release install uses the correspondence its provenance recorded; its fingerprint follows the HEAD frontend tree). It is in the required tier of `CAN_OPEN_DASHBOARD`: a stale bundle makes the capability DEGRADED, never BLOCKED, and `aeos doctor` exits 0; `runtime.frontend_dist` stays the critical existence check (no `index.html`: BLOCKED, exit 1). `aeos serve` (checkout mode) builds a STALE, MISSING or UNVERIFIED bundle once before it starts when the tree is a git checkout, `node_modules` matches the lockfile and `frontend/` is clean, never installs anything and never blocks the start. The build is atomic: `npm run build -- --outDir dist.next` (the Vite build record follows the configured outDir), then `dist` -> `dist.prev`, `dist.next` -> `dist`, `dist.prev` deleted; a failed, killed or timed-out build leaves `dist` untouched, a failed rename (a locked file on Windows) is undone and reported, and when `dist/index.html` is absent afterwards `ui_build` says MISSING with the remedy, not STALE. `dist.next` and `dist.prev` are gitignored. `/api/health` reports `ui_build` (`previous_status` after a rebuild), and `--no-ui-build` skips the rebuild. `index.html` and the SPA fallback are `no-cache`, hashed assets `immutable`, a missing asset is 404, and the UI reloads once on `vite:preloadError`. New `runtime.code_drift` (the commit `aeos serve` loaded against HEAD, backend paths only; `requirements.lock` now also in the `runtime.backend_deps` fingerprint) and a `post-merge` hook that reminds to restart (printed with `printf '%s\n'`, because sh's `echo` turned the `\a` of `.\aeos.ps1` into a BEL character; linted by `shellcheck` in CI and `scripts/gates.py` like `pre-push`). Evidence: E2 unit and git-subprocess tests on macOS arm64 with a fake build runner and a fake failing rename (no real npm build in tests); one real `npm run build -- --outDir dist.next` on macOS arm64 left `dist` untouched. NOT-PROVEN on Windows and macOS Intel.
- **The Control Center says when it or the server is out of date.** `aeos serve` puts a leftover `frontend/dist.prev` back before its rebuild safety checks (restoring needs no npm), so a valid old bundle is served with `--no-ui-build`, an out-of-date `node_modules`, a changed `frontend/` or no npm instead of every page returning 503, and `ui_build` always describes `frontend/dist` as it is on disk when serve starts (a restored bundle whose rebuild then fails is STALE, never MISSING). `GET /api/health` adds `freshness`: the build record tree of the bundle served now (read from disk on every request, never cached, so a page reloaded right after a manual rebuild is not told it is older than the server) and the code drift of this server process (`code_drift`, the same function as the Doctor's `runtime.code_drift`, git calls bounded at 5 s, cached 30 s per server, so a refetch makes no git call inside the window). The Vite build bakes its frontend tree into the bundle; an AppShell banner (text, icon, colour) shows "Tampilan lebih lama dari server: muat ulang halaman" with a reload button when the two trees differ, "Server menjalankan kode lama (<sha>): restart ./aeos serve" on backend drift, and a notice when `ui_build` is STALE or MISSING for the bundle the page runs (not in the Vite dev server, and not after a manual rebuild while serving, when the served tree differs from the one `ui_build` judged). When putting `dist.prev` back fails while `frontend/dist` is still there, the rebuild is not started (its swap could not succeed) and `ui_build` reports MISSING with the restore failure as the reason. Health is read with the existing query (refetch on focus after 30 s), no polling. Evidence: E2 unit tests (fake build runner, controllable clock, git call counter) and vitest component tests with a mocked health response on macOS arm64. NOT-PROVEN on Windows and macOS Intel, and in a browser against a real rebuild.
