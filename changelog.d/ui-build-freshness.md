### Fixed

- **Stale Control Center after git pull.** `git pull` updated the frontend source but `frontend/dist` (built 2026-10-26) was served for two days while five frontend commits were missing, and the Doctor only checked that `index.html` existed (LESSONS L23, owner request R28). `runtime.frontend_dist` now compares the Vite build record with `git rev-parse HEAD:frontend` through `release.ui_correspondence` (CONFIGURED `FRONTEND_STALE` on a mismatch, UNVERIFIED without a clean record; a release install uses the correspondence its provenance recorded) and its fingerprint follows the HEAD frontend tree. `aeos serve` (checkout mode) rebuilds a stale bundle once before it starts when `node_modules` matches the lockfile and `frontend/` is clean, never installs anything and never blocks the start; `/api/health` reports `ui_build`, and `--no-ui-build` skips the rebuild. `index.html` and the SPA fallback are `no-cache`, hashed assets `immutable`, a missing asset is 404, and the UI reloads once on `vite:preloadError`. New `runtime.code_drift` (the commit `aeos serve` loaded against HEAD, backend paths only; `requirements.lock` now also in the `runtime.backend_deps` fingerprint) and a `post-merge` hook that reminds to restart. Evidence: E2 unit and git-subprocess tests on macOS arm64 with a fake build runner (no real npm build in tests). NOT-PROVEN on Windows and macOS Intel.
