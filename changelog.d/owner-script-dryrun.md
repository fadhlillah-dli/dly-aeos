### Added

- **Owner script dry run with a capability diff (`scripts/owner_dryrun.py`, LESSONS L13 strike 3).** On 2026-10-28 an owner script passed a dry run against a database copy that had no secrets, and on the real system it activated two WORKER routes whose credential was not stored, so CAN_RUN_WORKER fell from READY to BLOCKED. The new harness copies the live database with sqlite3's online backup from a read-only connection (immutable when no writer is open, so nothing appears beside the live file) and `aeos.yaml` into a temporary data dir, mirrors which secret references the real store holds (names and expiry from `aeos secrets status`, never a value) into an in-memory store with dummy values, and runs the script's `run(client, username, password, ask)` against the real app through a TestClient with a temporary SUPER_ADMIN and the `--answer` values in order. The dry-run process has the null keyring, OpenBao at a closed loopback port, and refuses every TCP connect to a non-loopback address and to the loopback ports of the real OpenBao and Control Center. The Doctor runs without `--functional` before and after; the capability table and the changed checks are printed, and a capability that got worse, or a gating check of a capability that newly fails under an unchanged status (`BLOCKED -> BLOCKED`), ends with `OWNER_DRYRUN: DEGRADED` (exit 1) unless `--accept-degrade 'reason'` is given (exit 0, `DEGRADED-ACCEPTED`, never OK). A script without `run(...)`, a prompt with no answer left, a failing script, a real secret store that cannot be read (OpenBao sealed or stopped) or a copy not at the checkout's migration head is `OWNER_DRYRUN: FAIL` (exit 2); the temporary dir is removed in every case. The delegation brief now requires the dry run and its capability diff before owner commands are shown. Evidence: E2 unit tests on macOS arm64 against a synthetic live database in tmp (disabling the only keyed WORKER route is red with `CAN_RUN_WORKER: READY -> BLOCKED`, accepted with a reason exits 0, a script that changes nothing is OK and shows the keyed route READY only while its credential is in the presence set, a critical check that newly fails under an already BLOCKED CAN_RUN_WORKER is red, an unavailable real store fails before anything is copied, the script sees the null keyring and refused connects, the live file is byte-identical with no new files beside it, and the temporary dir is gone). NOT-PROVEN: a run against the owner's real database and real store, child processes of the Doctor probes (not network-isolated), and everything on Windows and macOS Intel until CI runs it.
