### Added

- **Owner script dry run with a capability diff (`scripts/owner_dryrun.py`, LESSONS L13 strike 3).** On 2026-10-28 an owner script passed a dry run against a database copy that had no secrets, and on the real system it activated two WORKER routes whose credential was not stored, so CAN_RUN_WORKER fell from READY to BLOCKED. The new harness copies the live database with sqlite3's online backup from a read-only connection (immutable when no writer is open, so nothing appears beside the live file) and `aeos.yaml` into a temporary data dir, mirrors which PERSONAL secret references the real store holds (names and expiry from `aeos secrets status` without `--include-office`, never a value; `office/*` is not mirrored and stays NO_ACCESS) into an in-memory store with dummy values, and runs the script's `run(client, username, password, ask)` against the real app through a TestClient with a temporary SUPER_ADMIN; `ask`, `input()` and `getpass.getpass()` all take the `--answer` values in order (getpass reads the terminal, not stdin, so it is routed too and its answer is not echoed). The dry-run process has the null keyring, OpenBao at a closed loopback port, and refuses every TCP connect to a non-loopback address and to the loopback ports of the real OpenBao and Control Center; only while the Doctor runs is the Control Center port open to it, so `host.port` sees a running server as `aeos doctor` does (CONNECTED) instead of a false PORT_BIND_DENIED. The Doctor runs without `--functional` before and after; the capability table and the changed checks are printed, and a capability that got worse, or any gating check that newly fails whatever the status did (`BLOCKED -> BLOCKED`, or `BLOCKED -> DEGRADED` because another check recovered), ends with `OWNER_DRYRUN: DEGRADED` (exit 1) unless `--accept-degrade 'reason'` is given (exit 0, `DEGRADED-ACCEPTED`, never OK). A script without `run(...)`, a prompt with no answer left (`no --answer left for prompt: ...`), a failing script, a real secret store that cannot be read (OpenBao sealed or stopped, or a PERSONAL reference UNKNOWN) or a copy not at the checkout's migration head is `OWNER_DRYRUN: FAIL` (exit 2); the temporary dir is removed in every case. The delegation brief (rule 10) and L13 keep the broad rule: every owner command or script that writes state is dry-run first, an owner script with this harness (its capability diff shown), any other command in-process against a temporary database or wrapped in a tiny owner script. Evidence: E2 unit tests on macOS arm64 against a synthetic live database in tmp (disabling the only keyed WORKER route is red with `CAN_RUN_WORKER: READY -> BLOCKED`, accepted with a reason exits 0, a script that changes nothing is OK and shows the keyed route READY only while its credential is in the presence set, a gating check that newly fails under an already BLOCKED CAN_RUN_WORKER is red, so is one that fails while the capability improves from BLOCKED to DEGRADED, a listener on AEOS_PORT gives host.port CONNECTED and no false BLOCKED while the script stays refused, getpass inside `run()` takes the answer queue and an exhausted queue fails, an UNKNOWN office row does not fail a PERSONAL dry run, an unavailable real store fails before anything is copied, the script sees the null keyring and refused connects, the live file is byte-identical with no new files beside it, and the temporary dir is gone). NOT-PROVEN: a run against the owner's real database and real store, child processes of the Doctor probes (not network-isolated), and everything on Windows and macOS Intel until CI runs it.
