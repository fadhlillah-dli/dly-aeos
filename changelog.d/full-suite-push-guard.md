### Added

- **The pre-push hook refuses a commit whose tree has no passing full-suite run.** `scripts/run_tests.sh` records a passing FULL run (no pytest argument that can select or deselect tests) on a CLEAN tree (clean before and after, HEAD unchanged) as `<tree> <head> <UTC time> <load average>` in `<git common dir>/aeos-full-suite-runs`, shared by every worktree; any other run prints one line saying why it was not recorded, and recording never fails a run (`scripts/full_suite_record.py` owns the format). `scripts/gates.py --hook` then fails each pushed commit (deletions skipped) whose tree has no record, with `full suite not run for tree <short> (<sha>): run scripts/run_tests.sh on a clean tree, or push with AEOS_PUSH_WITHOUT_FULL_SUITE='<reason>'`; with that reason set the guard is SKIPPED, never PASS. A local `gates.py` run says whether HEAD's tree has a record. Prevents the incident class of LESSONS L8 (strike 3, 2026-10-27: a branch tested only with targeted tests was pushed and CI went red). Evidence: E2 bite tests on macOS arm64 (no record, a record for another tree: FAIL with the message; record for this tree or the same tree under a new commit, also written in a linked worktree: PASS; reason: SKIPPED; deletion: not checked; a real `git push` through the hook refused and then allowed; `run_tests.sh` with a stand-in interpreter records a full clean pass and not a partial, failed or dirty run). On Windows the record comes from `scripts/run_tests.sh` run with Git Bash (a direct `python -m pytest` writes none), and `CONTRIBUTING.md` gives the one-push bypass for cmd (`cmd /c "set "AEOS_PUSH_WITHOUT_FULL_SUITE=<reason>" && git push"`, so the reason does not stay set in the window) and PowerShell. NOT-PROVEN on Windows (the runner, the hook and the cmd and PowerShell forms were not run there) and Intel macOS.
- **`conflict-markers` gate in `scripts/gates.py`.** `git diff --check <merge base with origin/main>..<tip>` (the pushed tip in hook mode, HEAD locally), only its "leftover conflict marker" findings, FAIL with `file:line`; a file whose only finding is a lone `=======` line (a markdown setext underline, which git also flags) passes; SKIPPED without `origin/main`. New lesson L22 (strike 2, 2026-10-27: a step whose failure had to stop the next one was chained with `;`, so a failed conflict resolution still committed its markers) with DELEGATION-BRIEF rule 18. Evidence: E2 bite tests on macOS arm64 with git 2.50 (committed `<<<<<<< ` line red naming the line; setext heading green while raw `git diff --check` flags it). NOT-PROVEN on Windows and Intel macOS.
- **`scripts/github_settings.py --settle SECONDS`.** When a read shows DRIFT, `--check` and the check after `--apply --yes` wait (default 10 s, `0` disables) and read once more; the verdict is the second read and the output says it waited. Prevents a false DRIFT from GitHub's read-after-write lag (2026-10-27: DRIFT seconds after an apply, OK minutes later). Evidence: E2 tests with the injected fake API and an injected sleep (stale then fresh: OK with the settled note; persistent drift: DRIFT; `--settle 0`: no wait). The real lag is NOT-PROVEN beyond that one observation.
- **Self-explaining memory-cap test.** Every assertion of `test_memory_cap_stops_the_worker` prints the result, `outcome_code`, `usage_summary`, `caps`, the pid's liveness and the load average; what it proves is unchanged. Observation for LESSONS L15 (the register has no notes column): on 2026-10-27 it failed once in a local full suite at load average about 10 to 14 (1 of 3 runs) and passed 12 of 12 isolated parallel runs under artificial CPU load; the failure text was not kept, so the cause is NOT-PROVEN.
