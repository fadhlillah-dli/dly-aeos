### Security

- **The broker never sends a credential to a model, on any route.** Owner request 2026-10-28 (use DeepSeek and the other best listed routes, with nothing sensitive in what the providers may train on). Before any request is forwarded - every route and pool, worker calls and feasibility probes - every string of the payload (all message roles, tool calls and their arguments, tool definitions) is scanned with `aeos.core.redaction` (token shapes plus the secret values AEOS loaded at run time; no copied patterns). A match is not sent: 403 `SENSITIVE_CONTENT_BLOCKED`, a `SENSITIVE_BLOCKED` broker request, the audit record `broker.model_proxy.sensitive_blocked` and the run event `run.model_call_blocked` with the detector kinds and a SHA-256 of each matched span (never the text), and the run is stopped as FAILED with that outcome code. No setting turns it off. Personal data such as e-mail addresses is deliberately not blocked (ADR-0127 states the residual risks). The redaction scan is now linear: the PEM block, the labelled unseal key and the look-behind patterns could backtrack quadratically (minutes on 2 MB), and a 2 MB request now scans in well under 200 ms; the guard does not refuse code or data that only looks like a token (a Go receiver `s.` or a JavaScript `this` followed by a member name such as `registerServiceWithHealthCheck`, `1//` floor division, `AIza` or `1//` inside an image data URI or a lockfile integrity hash), and it finds a token right after a JSON escape (`\n`, `\t`, `\"`, `\u00e9`, also JSON encoded twice) or a URL-encoded separator (`%3D`, `%26`, `%3F`). The redaction patterns of logs, errors, the repository secret scan and the Claude prompt guard are unchanged: a differential review before merge found that the first build had weakened the short Vault token pattern (a token after an escaped newline was no longer masked in logs); it is restored and `tests/unit/test_redaction_never_weaker.py` now keeps every shape origin/main caught, in every context, from being dropped (LESSONS L25). An investigation run whose request was refused blocks its task (reason `SENSITIVE_CONTENT_BLOCKED`, cleared only by an owner retry) instead of moving to the next hypothesis, and a refusal decides the run's outcome even when a quota stop, a shutdown or a lost lease came later (no attempt refund). ADR-0127 is ACCEPTED (owner request R32). Evidence: E2 unit and bite tests on macOS arm64 (GitHub token, OpenRouter key, AWS key id and PEM key refused on a `:free` route, a Go route and a probe; code diff, sha256, UUID, e-mail, long member names, Go receivers, floor division, an image data URI and a lockfile forwarded unchanged; the differential corpus red on the first build and green now). NOT-PROVEN on Windows and macOS Intel until CI runs, and against live providers (upstreams mocked).
