### Security

- **The broker never sends a credential to a model, on any route.** Owner request 2026-10-28 (use DeepSeek and the other best listed routes, with nothing sensitive in what the providers may train on). Before any request is forwarded - every route and pool, worker calls and feasibility probes - every string of the payload (all message roles, tool calls and their arguments, tool definitions) is scanned with `aeos.core.redaction` (token shapes plus the secret values AEOS loaded at run time; no copied patterns). A match is not sent: 403 `SENSITIVE_CONTENT_BLOCKED`, a `SENSITIVE_BLOCKED` broker request, the audit record `broker.model_proxy.sensitive_blocked` and the run event `run.model_call_blocked` with the detector kinds and a SHA-256 of each matched span (never the text), and the run is stopped as FAILED with that outcome code. No setting turns it off. Personal data such as e-mail addresses is deliberately not blocked (ADR-0127 states the residual risks). The redaction scan is now linear: the PEM block, the labelled unseal key and the look-behind patterns could backtrack quadratically (minutes on 2 MB), and a 2 MB request now scans in well under 200 ms; the short Vault token form no longer matches code such as `this.handleSubmitButtonClickedEvent`. Evidence: E2 unit and bite tests on macOS arm64 (GitHub token, OpenRouter key, AWS key id and PEM key refused on a `:free` route, a Go route and a probe; code diff, sha256, UUID, e-mail and long member names forwarded unchanged). NOT-PROVEN on Windows and macOS Intel until CI runs, and against live providers (upstreams mocked).
