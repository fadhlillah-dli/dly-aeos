### Added

- **Claude Code zsh word-split guard.** `scripts/claude_hooks/zsh_wordsplit_guard.py` is a fail-open `PreToolUse` hook for the Bash tool (registered in `.claude/settings.json` with matcher `Bash`): in a zsh session it denies, with the reason and the fix, `set -- $var` and `for x in $var` with one unquoted variable (zsh does not word-split it, so the loop gets one argument) and a command substitution holding a bare glob that is passed to pytest or `scripts/run_tests.sh` (a glob that matches nothing comes back empty and pytest runs the whole suite serially). Quoted expansions, explicit lists, the zsh split form `${=var}`, arrays assigned in the same command, `bash -c` strings, heredoc bodies and comments pass; any internal error exits 0 silently. Prevents the LESSONS L14 incident class (word-split and glob traps, 2026-10-26 to 2026-10-28). Evidence: E2 unit and subprocess bite tests on macOS arm64 (each trap denied with its own reason; near misses, bad JSON and other tools allowed). NOT-PROVEN on Windows and Intel macOS, and inside a live Claude Code session (the hook protocol was read from the documentation, not exercised).
- **The zsh guard also denies an unquoted glob that matches no file.** zsh's NOMATCH error stops the whole command before anything runs; four maintainer commands on 2026-10-28/29 were lost that way (for example `grep -rn x backend --include=*.py`). The hook now matches each unquoted glob word against the session's working directory (or the directory of a plain `cd` before it) and denies one that matches nothing, with the fix in the reason. Quoted, escaped, expanded and braced words, assignments, `[[ ]]`, `(( ))`, `case` patterns and commands that turn NOMATCH off are left alone. Known false deny: a file created earlier in the same command (the reason names `setopt nonomatch;`). Evidence: E2 unit run on macOS arm64; 6 bite tests red on the previous hook.
