### Changed

- **All git worktrees live in one folder next to the main checkout.** The owner saw many `dly-aeos-wt-*` folders appear next to the main checkout and asked why they are not one folder (2026-10-28). One worktree per parallel branch stays (the main checkout stays on `main` because the running Control Center is served from it), but `scripts/worktree.py add <name> <branch>` now creates `<main checkout>-worktrees/<name>` (for this repository `~/Documents/dly-aeos-worktrees/<name>`) instead of the sibling `<main checkout>-wt-<name>`. `add` creates the folder when it is missing, as a real directory, and refuses with nothing created when the folder is a symlink, junction or reparse point or exists as a file (LESSONS L4: a link can be followed by a removal), or when a legacy worktree already uses the name. `remove <name>` also finds a worktree made before this change at the legacy sibling path when that path is a registered worktree, refuses a name that exists in both places as ambiguous, and after a removal from the folder deletes the folder only when it is now empty and a real directory (`os.rmdir`, never a recursive delete). `list` prints the folder and flags `legacy-location` worktrees with a hint to move them with `git worktree move <old path> <main checkout>-worktrees/<name>` (create the folder first and give the full target path: on an existing directory git nests the worktree under its old name; the move renames the directory and does not follow links). The module docstring, the `--help` text and `CONTRIBUTING.md` describe the layout. Bite tests in `tests/unit/test_worktree_tool.py` (hermetic repositories in a temporary directory): the symlink and file folder refusals, the ambiguity refusal and the legacy-name refusal each assert their own message; near misses (a second worktree in an existing folder, a non-empty folder kept, a link folder never removed, a legacy worktree removed) are green; 20 of them are red on the previous code. Evidence E2 (unit run on macOS arm64; ruff, mypy `--platform darwin` and `--platform win32`). NOT-PROVEN on Windows (junction folder) and macOS Intel until CI runs them.
