### Added

- **A fixed timing bound in a test states its margin.** A fixed time bound measures the machine, not the code: on 2026-10-28 three timing tests failed with correct code (a 200 ms wall-clock bound under load, a 0.5 s CPU bound on the Intel macOS runner that took 0.54 s there and 0.13 s on arm64, and a bite test whose 0.3 ms runs were noise), LESSONS L15. `tests/unit/test_timing_bounds_declared.py` AST-scans every `tests/**/*.py` file and fails, with `<path>:<line>: fixed timing bound without a '# timing-cap: <margin>' comment`, on an `assert` that compares a measured time with a fixed bound unless a `# timing-cap: <margin>` comment of at least 10 characters sits on the assert's line or directly above it. A measured time is a `time.perf_counter`, `monotonic`, `process_time` or `time` reading (and `_ns` variants, bare and star imports, module aliases, and a clock passed around uncalled such as `clock = time.perf_counter` or a parameter default); a name, dotted attribute or container assigned or filled from one, to a fixed point over the file, also from an enclosing scope; an attribute a class of the file sets on `self` from one (a timer used as `with Timer() as t`); the result of a function of the file that returns or yields one (also a nested function, a method, a same-named fixture parameter and a `with` target; for a returned tuple only the timed element); a parameter of a function of the file that some call passes one to; and a result attribute or string key named like a measured time (`res.duration_s`, `rr.duration_ms`, `run["elapsed"]`), whose clock was read in product code. A comparison bounds a measured time by a constant when one side is measured and the other not (unless the measured side is a ratio of two measured times), or when both are measured, neither is scaled or a ratio, and one is shifted by a constant: `t1 < t0 + 0.5` and an assert on `deadline = time.monotonic() + 5` are fixed bounds, `took <= 8 * max(small, 0.02)` and `t0 <= t1` are relative. Polling loops are not asserts, and a fixed-bound comparison moved out of the assert (`slow = [...]` then `assert not slow`, or a helper that returns `elapsed < 0.5`) still counts. Bite tests in a temporary directory are red with their finding text (a plain bound, a best-of helper on CPU time, the timed element of an unpacked tuple, a bound inside `and`, bare, star and aliased imports, a bound moved out of the assert, a timestamp shifted by a constant and an asserted deadline, an attribute, a timer class and a timer context manager, a bound inside a helper or returned by one, a clock alias, a clock parameter default and a closure, a function reference, a static method, a global, a fixture and a heap, a product-measured duration attribute and key, a cap that is too short, two lines up or inside a string) and green for the near misses (a declared cap, a ratio, a multiple, two ordered readings, deadline polling, a linear-growth helper, a count of timing values, the untimed sibling of an unpacked tuple, a configured `timeout_s`). The 20 existing fixed bounds on main were measured on macOS arm64 (load average 3 to 65) and each now states its margin; five changed: the detached-survivor test in `test_verification_procs.py` compares against the grace period it rules out instead of an arbitrary 1.0 s, the allow-listed-helper test there gets a 40 s helper grace and is bounded by that grace (a run is the 3.5 s helper plus 0.1 to 0.3 s; a reap that waits the grace out still fails), two process-tree bounds there move from 30 s to 45 s (runs of 3.0 s and 3.2 to 3.8 s; the 60 s sleeps they rule out still fail), and the ReDoS test in `test_owner_commands_paste_safe.py` allows 5 s instead of 0.5 s wall clock (a match takes about 15 us; the old regex doubled per repeat and never returns at 40). `CONTRIBUTING.md` states the rule and prefers relative checks. Evidence E2 (unit run on macOS arm64); NOT-PROVEN on Windows and Intel macOS until CI runs them. Known gaps, tracked as follow-up work (review of a317e6d): a deadline written in milliseconds, a helper taking *args/**kwargs, timer objects (properties, a box set in a context manager), and timestamps written by a nested scope into the enclosing one still escape the scan; none of them changes a test result, they only escape the lint.
