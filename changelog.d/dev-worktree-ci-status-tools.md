### Added

- **Safe worktree tool (`scripts/worktree.py`).** `list`, `add` and `remove` for git worktrees. `list` shows per worktree the branch, head, merged into origin/main, pushed with the same sha, created-by-tool marker and a count of symlinks, junctions and reparse points (walked without following them). `add` creates `<main checkout>-wt-<name>` and never creates a link. `remove` refuses a worktree that holds a link (a `.venv` junction once made `git worktree remove` delete half of a real virtual environment), a worktree without the marker, uncommitted changes, and a branch that is neither merged nor pushed; `--unlink-links` removes only the link entries themselves and scans again. Evidence: E1 static review and E2 unit tests run on macOS arm64 (symlink bite tests: refusal, sentinel directory intact after `--unlink-links`, near-miss real `node_modules` accepted). The Windows junction test is skipped on macOS: junction handling is NOT-PROVEN on Windows, and so is the whole tool on macOS Intel until CI runs it.
- **CI verdict for one commit (`scripts/ci_status.py`).** One verdict (GREEN, RED, PENDING, SUPERSEDED, ERROR, TIMEOUT) for one exact sha, from `gh api` check runs and the required status check contexts of the repository rulesets, with `--pr`, `--expect-sha`, `--after-merge`, `--wait --deadline` and `--report`. It prevents ad-hoc watchers from reading an empty, queued or incomplete check list as green: an empty list is PENDING, a required check that has not reported is PENDING, a cancelled run is SUPERSEDED only when a newer run exists on the same branch, and the latest attempt of each check decides. Evidence: E2 unit tests on macOS arm64 against fixture JSON through an injected runner (no network). Not run against the live GitHub API, not run on Windows or macOS Intel (NOT-PROVEN); classic branch protection and commit-status contexts are not read.
