### Added

- **Safe worktree tool (`scripts/worktree.py`).** `list`, `add` and `remove` for git worktrees. `list` shows per worktree the branch, head, merged into origin/main, pushed with the same sha, created-by-tool marker and a count of symlinks, junctions and reparse points (walked without following them). `add` creates `<main checkout>-wt-<name>` and never creates a link. `remove` refuses a worktree that holds a link (a `.venv` junction once made `git worktree remove` delete half of a real virtual environment), a worktree without the marker, uncommitted changes, and a branch that is neither merged nor pushed; `--unlink-links` removes only the link entries themselves and scans again. Evidence: E1 static review and E2 unit tests run on macOS arm64 (symlink bite tests: refusal, sentinel directory intact after `--unlink-links`, near-miss real `node_modules` accepted). The Windows junction test is skipped on macOS: junction handling is NOT-PROVEN on Windows, and so is the whole tool on macOS Intel until CI runs it.
- **CI verdict for one commit (`scripts/ci_status.py`).** One verdict (GREEN, RED, PENDING, SUPERSEDED, ERROR, TIMEOUT) for one exact sha, from `gh api` check runs and the required status check contexts of the repository rulesets, with `--pr`, `--expect-sha`, `--after-merge`, `--wait --deadline` and `--report`. It prevents ad-hoc watchers from reading an empty, queued or incomplete check list as green: an empty list is PENDING, a required check that has not reported is PENDING, a cancelled run is SUPERSEDED only when a newer run exists on the same branch, and the latest attempt of each check decides. Evidence: E2 unit tests on macOS arm64 against fixture JSON through an injected runner (no network). Not run against the live GitHub API, not run on Windows or macOS Intel (NOT-PROVEN); classic branch protection and commit-status contexts are not read.
- **`ci_status.py --required-only`, the INFRA verdict, and three review fixes.** By default any failed check is RED, as before. `--required-only` computes the verdict from the required contexts only (GREEN when all are success, skipped or neutral, PENDING while one is missing, queued or running, RED only when a required one failed), lists a non-required failure with `[NON-REQUIRED FAILED]` and names it in the last line, for example `CI: GREEN <sha> (non-required failed: commit subjects [G1])`; this covers the PR #21 case, where only the non-required `commit subjects [G1]` failed while required jobs were still running and the verdict read RED. A required job cancelled because GitHub never gave it a runner (output or annotation says it was not acquired by a runner, as when hosted macOS arm64 capacity ran out while the job was queued) is INFRA with exit code 4, never RED: re-run it. Also fixed: `worktree.py remove --unlink-links` no longer counts the files git lists below a junction as uncommitted changes (Git for Windows reports a junction as a plain directory and walks into it), `ci_status.py --wait` no longer polls sooner than the 30 s interval before the deadline (it sleeps the time left and reports TIMEOUT), and an unwritable `--report` path ends with one `CI: ERROR <sha>` line and exit 2 instead of a traceback that a watcher reads as RED. Evidence: E2 unit tests on macOS arm64 against fixture JSON (non-required failure with required success is GREEN with `--required-only` and RED without, a required failure is RED either way, a required check still running is PENDING; the not-acquired cancellation is INFRA through an annotation and through the output text, a plain cancellation stays RED, a failure or a second plain cancellation is not hidden; a real directory in a temporary repository reproduces the Windows view of a junction). Not run against the live GitHub API; the Windows junction removal is NOT-PROVEN until a Windows run passes.
