### Changed

- **CI rebalanced toward ten minutes (ADR-0115 amendment 2026-10-27).** Measured on GitHub run 40424256888 (PR #26, per-job wall time including setup): backend shard 1 / shard 2 took `windows-latest` 9.3 / 8.8 min, `macos-latest` 11.0 / 5.5, `macos-26-intel` 9.6 / 7.6, the verifier 8.0; the whole run 11.1 min. Causes: shard 1 of every OS also ran the G1 static checks (58 s on `macos-latest`, 10-16 s elsewhere), and `tests/ci_durations.json` still held seconds from before the PR #26 speedups, one split for three OSes that weigh files differently (test time of the two shards: 1,216 s and 697 s on `macos-latest`, 1,615 s and 1,569 s on `windows-latest`). Now: the G1 static checks (ruff, mypy darwin and win32, secret scan) run once as `static checks [G1] (ubuntu-latest)`, which all three required `backend [G1,G2] (<os>)` aggregators `need`, so every shard is the same job; `scripts/ci_durations.py --os LABEL FILE...` scales each OS to the same total and averages, and the committed weights are rebuilt from the 6 reports of that run; `windows-latest` runs 3 shards (`backend shard K/3 [G2]`), the macOS hosts keep 2 (5 concurrent macOS jobs on GitHub Free, 7 already). Predicted shard test seconds (model from the same reports, which reproduces the old measured split within 31 s), old measured to new: Windows 482 / 469 to 296 / 311 / 344, `macos-latest` 534 / 295 to 432 / 397, Intel macOS 496 / 406 to 450 / 452. The required check names are unchanged; shard job names now read `backend shard K/N [G2] (<os>)` and are not required. `tests/unit/test_ci_shards.py` collects the whole suite with the exact `-m` expression of the CI shard step and proves for 2 and 3 shards that the shards are disjoint (by node id and by file) and together equal the unsharded collection.
- **Measured on the change's own CI run 40427552409.** The whole run took 10 min 47 s; the static job 62 s (mypy steps 30 s); all backend required checks were done at 9.6 min, and the last required check (the Intel bootstrap) waited for a macOS slot. The macOS jobs add up to about 2,669 s on 5 slots, which sets the floor. Known pre-existing gap, not changed here: the 26 `integration`/`network` tests run in no CI job.
- **CI structure guards hardened.** The expected job and check names are pinned in `tests/unit/test_ci_gates.py` (no comparison with `origin/main`, which a pull request checkout lacks); the two mypy platforms are separate steps without a `shell:` override; no backend job's `actions/checkout` may carry a `with:` key, and the static job sets up exactly like the shard jobs; `scripts/ci_durations.py` exits 2 with a clear message for an OS with a total of 0 s and for an `--os` label that is a file name.
